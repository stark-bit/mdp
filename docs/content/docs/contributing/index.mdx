Thanks for helping out! Bug reports, fixes, features and documentation are all
welcome.

- [Development setup](./development.mdx): build the server and run your checkout.
- [Testing](./testing.mdx): the test suites and how to write tests.
- [Architecture](./architecture.mdx): how the server and the page fit
  together, and where to make a change.

## Reporting a bug

Open an [issue](https://github.com/sammaji/markdown-preview.nvim/issues) with:

- your system and how you installed the server (`markdown-preview --version`)
- a small markdown file and the configuration that show the problem
- the [log](../faq.mdx#where-is-the-log), ideally with
  `MP_LOG_LEVEL=debug`

## Before you start

For anything larger than a small fix, open an issue first so we can agree on
the approach. [`UPSTREAM_ISSUES.md`](https://github.com/sammaji/markdown-preview.nvim/blob/master/UPSTREAM_ISSUES.md) triages the
issues of the original plugin, and is a good place to find work.

## Pull requests

- Target the `master` branch.
- Keep pull requests focused on one change.
- Add or update tests: a fix comes with a test that fails without it, see
  [Testing](./testing.mdx#writing-tests).
- Run `./test.sh` and the [checks](./development.mdx#checks).
- Describe what you changed and how you tested it.
- Add an entry to [`CHANGELOG.md`](https://github.com/sammaji/markdown-preview.nvim/blob/master/CHANGELOG.md) under `Unreleased` for
  user-facing changes.
- Update the documentation for anything users see, see [Working on the
  docs](./development.mdx#working-on-the-docs). New options go in
  [the configuration reference](../configuration.mdx).

## Releasing

For maintainers:

1. Bump `version` in `Cargo.toml` and rename `Unreleased` in `CHANGELOG.md` to
   the new version.
2. Run `./test.sh`, and the [manual checks](./testing.mdx#manual-checks).
3. Commit and push to `master`.
4. Run `./release.sh`. It tags the version from `Cargo.toml` and pushes the
   tag, and the release workflow builds the binaries and publishes the GitHub
   release.

Users download the release matching the tag, so the tag must exist before
announcing an update.
