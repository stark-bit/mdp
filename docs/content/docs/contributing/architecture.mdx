```text
┌──────────────────────┐  HTTP + WebSocket  ┌───────────────┐
│  server (Rust)       │ ─────────────────▶ │ preview page  │
│  src/                │ ◀───────────────── │ (browser)     │
│  page embedded       │                    │ app/          │
└──────────────────────┘                    └───────────────┘
        ▲ reads
        │
   markdown files on disk
```

Two parts:

- **The server** (Rust, one binary) parses the command line and config file,
  watches the previewed files on disk, serves the page, and pushes the file
  contents to it over a WebSocket. It has no markdown renderer.
- **The page** (a Next.js app, exported as static files and embedded in the
  binary) renders the markdown in the browser and draws the diagrams.

## Repository layout

| Path                      | What it is                                                                                      |
| ------------------------- | ----------------------------------------------------------------------------------------------- |
| `src/main.rs`             | Entry point: logging, the Tokio runtime, `--version`.                                            |
| `src/config.rs`           | The options: config file (`markdown-preview.toml`) and command-line flags.                        |
| `src/server.rs`           | The HTTP server: routes, WebSocket, file targets and watching, local images, themes, security, opening the browser. |
| `src/opener.rs`           | Opening a URL in a browser on each system, with fallbacks (WSL).                                  |
| `src/logger.rs`           | The log file.                                                                                    |
| `build.rs`                | Builds `app/` into `app/out` before the server is compiled.                                       |
| `app/src/components/`     | The page's React components: `preview.tsx`, the theme toggle and download button.                 |
| `app/src/lib/markdown/`   | The markdown-it renderer and its plugins (alerts, images, front matter, fences, KaTeX, PlantUML). |
| `app/src/lib/`            | Diagrams, the diagram viewer, HTML export (`export-html.ts`), the WebSocket connection and message types. |
| `app/public/_static/`     | Files served as they are: `markdown.css`, `highlight.css`, js-sequence-diagrams.                  |
| `examples/features.md`    | A document that uses every feature.                                                               |

## A preview, step by step

1. `markdown-preview note.md` parses the config file and flags into a
   `Config`, and binds a port (see [the port
   fallback](../configuration.mdx#port-unset)).
2. The server canonicalizes the root (the working directory, or `--root`).
3. For each previewed file it prints the URL
   `http://localhost:<port>/files/<path relative to the root>` and opens it
   in the browser, unless `--no-open`.
4. The page connects to `/ws?path=<its url path>`. The server resolves the
   path to a markdown file under the root and reads it from disk.
5. A `notify` watcher watches the parents of the previewed files. On a
   change, the file is read again and pushed to the page as
   `refresh_content`.
6. The page renders the markdown and draws the diagrams.

The server exits cleanly on Ctrl-C. Several servers can run at once, each
with its own port and token.

## The WebSocket protocol

Defined in [`app/src/lib/protocol.ts`](https://github.com/sammaji/markdown-preview.nvim/blob/master/app/src/lib/protocol.ts). The
server sends one message, `refresh_content`, with the file's lines, name,
title, theme and options. The page sends nothing; it reconnects with backoff
if the connection drops.

## HTTP routes

| Route                    | Serves                                                                   |
| ------------------------ | ------------------------------------------------------------------------ |
| `/`                      | the page (`index.html`)                                                  |
| `/files/<path>`          | the page for a markdown file under the root, or an image, audio or video file |
| `/ws?path=<page>`        | the WebSocket of the page at url path `<page>`                           |
| `/_static/markdown.css`, `/_static/highlight.css` | `markdown_css` / `highlight_css`, or the built-in file |
| `/_theme/theme.css`      | `theme_css`, cleaned up for the browser, or an empty file                |
| `/_theme/<path>`         | font files from the theme's folder                                       |
| `/_assets/<path>`        | an image, audio or video file, resolved against the file's directory     |
| anything else            | the embedded file from `app/out`, or 404                                 |

## Security

The preview shows your files, and browsers let any web site talk to
`localhost`, so:

- The server listens on `127.0.0.1` unless `open_to_the_world` is set.
- The WebSocket only accepts connections whose `Origin` is the page itself, so
  another web site can't read the file.
- `/_assets/` only serves image, audio and video files, and `/_theme/`
  only font files from the theme's folder.
- `/files/` only serves files under the root, the working directory when the
  server started or `--root`. A path with `..`, an absolute path, or one that
  leads out through a symlink is a 404; the resolved path must still be
  under the root. Of those files it serves markdown files (as the page) and
  image, audio and video files.
- With `open_to_the_world`, the server makes a random 128-bit token.
  Pages, local files, the theme and the WebSocket need it, from the `?token=`
  in the URL or the cookie the page sets. The page's own scripts and styles
  don't.

## The page

The page is a single client-side React component,
[`preview.tsx`](https://github.com/sammaji/markdown-preview.nvim/blob/master/app/src/components/preview.tsx). For each
`refresh_content`, it:

1. renders the lines with markdown-it (`app/src/lib/markdown/`). Code fences
   for diagrams become placeholders.
2. replaces the document, keeping the state of open `<details>`
   (`details.ts`).
3. draws the diagrams (`diagrams.ts`). Each library is loaded only when the
   document has a diagram of its kind, and a broken Mermaid diagram keeps its
   last good drawing.

Styles come in layers: `app/src/app/globals.css` (the page and the default
shadcn/ui theme variables, in a CSS layer so any theme overrides them), then
`markdown.css` and `highlight.css`, then the user's theme.

## Builds and releases

`cargo build` runs `build.rs`, which builds the page with `pnpm build` into
`app/out`. `src/server.rs` embeds `app/out` with `include_dir!`, so the binary
contains everything.

The release workflow (`.github/workflows/release.yml`) runs on a `v*` tag. It
builds the binary for each platform (FreeBSD through `cross`), names it
`markdown-preview-<platform>`, and publishes the archives as a GitHub release.
`distribution.spec.ts` checks that these names agree.
