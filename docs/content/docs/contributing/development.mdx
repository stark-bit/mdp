## Requirements

- [Rust](https://rustup.rs) 1.86 or newer
- Node.js 20.9 or newer with [pnpm](https://pnpm.io) (or npx, which fetches
  pnpm)

## Build

```sh
git clone https://github.com/sammaji/markdown-preview.nvim.git
cd markdown-preview.nvim
cargo build --release
```

`cargo build` also builds the page (`app/`) whenever a file in it changed, and
installs its dependencies first if `app/node_modules` is missing. The page is
embedded into the binary. To skip the page build and reuse the existing
`app/out`, set `MKDP_SKIP_PAGE_BUILD=1`.

## Run your checkout

```sh
./target/release/markdown-preview README.md
```

or put the binary on your `PATH` to use it as an installed one.

## Making changes

| You changed          | To see it                                                        |
| -------------------- | ---------------------------------------------------------------- |
| `src/` (the server)  | `cargo build --release`, then restart the server                 |
| `app/` (the page)    | the same: the page is embedded in the binary                     |

The page is embedded at compile time, so a rebuilt binary always carries the
current page.

To work on the page with hot reload, run `pnpm dev` in `app/`. It serves the
page without a server, so it shows "Open this page by running the preview
server on a markdown file."; this is useful for styling, less so for anything
that needs a live connection.

[`examples/features.md`](https://github.com/sammaji/markdown-preview.nvim/blob/master/examples/features.md) uses every feature; preview it
to check a change by eye.

## Working on the docs

This site is a [Fumadocs](https://fumadocs.dev) app in `docs/`. The pages are
MDX files in `docs/content/docs/`, and `meta.json` files set the order of the
sidebar. Run it with hot reload:

```sh
cd docs
pnpm install
pnpm dev
```

and open `http://localhost:3000`. Link to other pages by their file, like
`[Testing](./testing.mdx#writing-tests)`; the site turns these into page
links. In MDX, `{`, `}` and `<` outside code start JavaScript and JSX, so put
them in backticks. For notes, use `<Callout>` (`type="info"`, `"warn"` or
`"error"`) rather than GitHub's `> [!NOTE]`.

`pnpm build` exports the static site to `docs/out`. The site is hosted on
Vercel at [mkdp.sammaji.com](https://mkdp.sammaji.com), from the `docs/`
directory.

## Checks

Run these before opening a pull request:

```sh
cargo fmt --check
cargo clippy --all-targets

cd app
pnpm typecheck
pnpm build
```

and the tests, see [Testing](./testing.mdx).

## Debugging

Start the server with debug logging:

```sh
MP_LOG_LEVEL=debug MP_LOG_FILE=/tmp/mkdp.log ./target/release/markdown-preview examples/features.md
```

and follow the log with `tail -f /tmp/mkdp.log`. Without these variables, the
log is `markdown-preview-<uid>.log` or `markdown-preview-<uid>.1.log`,
whichever is newer (`markdown-preview.log` on Windows), in the system temp
directory, and debug logging without `MP_LOG_FILE` writes a new
`markdown-preview-<uid>.debug-<time>-<pid>.log` for each session. The page
logs to the browser console.

The URL is printed on stdout; log lines go to the log file, not to stdout.
Use the `info!`, `debug!` and `error!` macros from `src/logger.rs`.

## Project conventions

- Tests live in their own files: `src/<module>_test.rs` next to the module,
  `tests/` for the binary, `app/test/`, `e2e/tests/`. Application files only
  include them with `#[cfg(test)] #[path = "<module>_test.rs"] mod tests;`.
- Comments explain why, not what.
- Options are config file keys and command-line flags, read once at startup
  by `src/config.rs`; new options go in [the configuration
  reference](../configuration.mdx).
