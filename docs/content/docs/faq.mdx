## The page does not update

The server watches the file on disk and pushes every change to the page.

- Make sure the file you edit is the one you passed to `markdown-preview`.
- The page follows the file on disk. Changes you have not saved are not
  previewed.
- The file must stay under the server's root (the directory it started in, or
  `--root`). A page that moved out of it stops refreshing.

## The preview URL gives a 404

The URL names the file's path relative to the server's root, and the server
only serves files under it. Run `markdown-preview` from the directory that
contains the file, or point `--root` at it. `..`, absolute paths and symlinks
that leave the root give a 404 by design.

## The port I asked for is not used

With `--port` (or `port` in the config file), the server tries the next 20
ports when yours is taken — the printed URL shows the one it got. Pin the
port for SSH forwarding by freeing it first; the server exits with an error
when all 20 are taken.

## How do I change between the dark and light theme?

The theme follows your system preference, or `theme` if it is set. To switch
it in the page, click the sun or moon button in the header. See [Themes and
custom CSS](./features/themes.mdx).

## Can a theme use my own fonts?

Yes. A font the theme names in `--font-sans` or `--font-mono` is used if it is
installed on your system. A font file can also sit next to the theme, loaded
with a relative `@font-face` URL, or the theme can `@import` it from Google
Fonts. See [Fonts](./features/themes.mdx#fonts).

## How do I open the preview in a new browser window?

Give `browser` as a command with its arguments; the URL is appended. See [A new
browser window](./features/browser.mdx#a-new-browser-window).

## The browser does not open in WSL

See [WSL](./features/browser.mdx#wsl).

## How do I preview a file on a remote machine?

Run the server there with `--no-open`, forward the preview's port over SSH,
see [Remote machines](./features/browser.mdx#remote-machines).

## How do I open the preview on my phone?

Turn on `open_to_the_world` and open the preview URL, token included, on the
phone. See [Sharing on your network](./features/browser.mdx#sharing-on-your-network).

## My Chart.js charts stopped rendering after upgrading

Charts use Chart.js 4. Configs written for Chart.js 2 need to be migrated, see
the [Chart.js migration guide](https://www.chartjs.org/docs/latest/migration/v3-migration.html).

## Where is the log?

In the system temp directory, named `markdown-preview-<uid>.log`
(`markdown-preview.log` on Windows). Once it passes 1 MB the log moves to
`markdown-preview-<uid>.1.log`, and back again when that one fills up, so
look at the newer of the two. For more detail, start the server with:

```sh
MP_LOG_LEVEL=debug MP_LOG_FILE=/tmp/markdown-preview.log markdown-preview note.md
```
