## Refreshing

The page shows the file on disk, and the server watches it: every time you
save an edit in any editor, the page updates by itself, without a reload.

No save step is involved — the page follows the file, not your editor. Edit
in vim, VS Code or `cat >> note.md`; the server only sees the file change.

While you edit, the page keeps what you were looking at:

- A Mermaid diagram with a syntax error keeps showing its last good drawing,
  dimmed, until it is valid again.
- `<details>` blocks you opened or closed on the page stay that way.

## Page URLs and links between files

A file under the server's root is previewed at its path relative to that
directory, so `docs/guide.md` opens at:

```text
http://localhost:8090/files/docs/guide.md
```

The root is the directory the server started in, or the directory given with
`--root`. A file not under the root is previewed at its full path instead:

```sh
markdown-preview ~/notes/ideas.md --root ~/notes
```

Links between markdown files work in the preview. Clicking this one opens the
page of `docs/guide.md`:

```markdown
See the [guide](docs/guide.md).
```

The file is read from disk, as it was saved. Images in it are found next to
it.

The URL can only name files inside the root: `..`, absolute paths, and
symlinks that point elsewhere give a 404. Files that aren't markdown aren't
shown, except images, audio and video, which a page may link to.

## The page

- The header shows the file name. Hide it with
  `preview_options = { disable_filename = true }`.
- The tab title is `page_title`, where `${name}` is the file name.
- The sun or moon button in the header switches between the light and
  dark theme.
- The header says "Disconnected" when the page loses its connection to the
  server (it reconnects by itself).
- `preview_options = { content_editable = true }` lets you edit the page to
  try out wording. The edits are not written to the file, and the next
  refresh replaces them.
